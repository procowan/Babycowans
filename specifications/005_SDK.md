# Babycowans Protocol V1.0.0 SDK Specification

This specification defines the implemented TypeScript developer surface for `@babycowans/core-sdk`.

## 1. Package identity

- Package: `@babycowans/core-sdk`
- Version: `1.0.0`
- Module type: `module`
- Package manager: `yarn@1.22.22`

The SDK is layered: high-level `BabycowansSDK` composition sits above low-level builders, PDA helpers, account/read utilities, transaction helpers, metadata helpers, Event Decoder, and errors.

## 7. Canonical developer flow

1. Select one of the six canonical ecosystems.
2. Preserve the selected ecosystem as the Application's on-chain state.
3. Register or atomically bootstrap the Application.
4. Compose subsequent payments, membership, rewards, token gating, gate-policy, audit, read, and event flows from current SDK primitives.
5. Keep wallet signing outside SDK custody.

## 8. Application bootstrap

`bootstrapApplication()` composes the canonical application bootstrap flow. Repository onboarding/examples provide the interactive Arrow Keys ecosystem-selection experience.

## 9. Rewards

The current high-level reward API is `createReward()`, `claimReward()`, and `cancelReward()`. The current SDK does not expose RewardCampaign APIs.

## 10. Membership

## 11. Token gating

- `configureTokenGate()`
- `verifyGateAccess()`

Composable GatePolicy operations are available through the low-level instruction-builder layer where the high-level client does not duplicate protocol primitives.

## 12. Read API and Event Decoder

- `getApplication()`
- `getMembership()`
- `getReward()`
- `getAuditHistory()`
- `decodeEvents()`

Decoded events are transaction-log observations; integrations must apply their required Solana transaction-success and commitment/finality policy before treating them as committed state.

## 13. Signer boundary

The SDK must not custody user seed phrases or browser-wallet private keys. Wallet-owned signing remains an external trust boundary.

## 14. Token compatibility

The SDK preserves SPL Token and Token-2022 compatibility boundaries and passes explicit token-program identity where required.
