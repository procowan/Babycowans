# Babycowans Protocol API Specification

## 1. Purpose

This specification defines the public API exposed by the Babycowans SDK.

The API is the canonical interface used by applications integrating with the Babycowans Protocol.

The API abstracts:

- account discovery
- PDA derivation
- instruction construction
- transaction submission
- account decoding
- event handling

Applications should interact with the SDK API instead of directly using low-level Solana primitives.

---

## 2. Design Goals

The API is designed to be:

### Stable

Public interfaces remain backward compatible within Version 1.

### Deterministic

Identical inputs always produce identical outputs.

### Strongly Typed

Every method accepts and returns documented types.

### Minimal

Every operation has exactly one canonical API.

### Predictable

Hidden side effects are prohibited.

---

## 3. Client

Applications create one client instance.

Example:

```typescript
const client = new BabycowansClient(...)
```

The client exposes every protocol capability.

---

## 4. Protocol API

Protocol administration methods include:

- initializeProtocol()
- nominateProtocolAuthority()
- acceptProtocolAuthority()
- setProtocolPause()

Only protocol authorities may execute administrative methods.

---

## 5. Asset API

Canonical asset methods include:

- registerAsset()
- updateAssetStatus()
- getAsset()
- listAssets()

Applications never register arbitrary assets.

Only canonical Babycowans assets are supported.---

## 6. Application API

Application methods include:

- registerApplication()
- nominateApplicationAuthority()
- acceptApplicationAuthority()
- updateApplicationStatus()
- getApplication()
- listApplications()

Applications are identified by their canonical application identifier.

---

## 7. Application Asset API

Methods include:

- configureApplicationAsset()
- getApplicationAsset()
- listApplicationAssets()

Applications may configure only registered canonical assets.

---

## 8. Gate Policy API

Methods include:

- createGatePolicy()
- updateGatePolicy()
- getGatePolicy()
- listGatePolicies()

Gate verification remains deterministic.

---

## 9. Reward API

Methods include:

- createRewardCampaign()
- updateRewardCampaign()
- getRewardCampaign()
- listRewardCampaigns()

Reward distribution follows protocol rules.

---

## 10. Payment API

Example:

```typescript
await client.pay({

    application,

    asset,

    payer,

    amount

})
```

The SDK derives every required PDA automatically.---

## 11. Verification API

Example:

```typescript
const result = await client.verifyAccess({

    application,

    asset,

    wallet

})
```

The returned object is strongly typed and contains the verification result.

---

## 12. Event API

Applications may subscribe to protocol events.

Example methods:

- onProtocolInitialized()
- onAssetRegistered()
- onApplicationRegistered()
- onPaymentProcessed()
- onGateAccessVerified()
- onRewardDistributed()

Applications should consume decoded events instead of raw program logs.

---

## 13. Account API

Typed account access includes:

- getProtocol()
- getAsset()
- getApplication()
- getApplicationAsset()
- getGatePolicy()
- getRewardCampaign()

Every returned account is fully decoded.

---

## 14. Error Model

The API exposes typed protocol errors.

Examples include:

- ProtocolPausedError
- InvalidAssetError
- InvalidApplicationError
- InvalidAmountError
- InvalidAuthorityError

Raw program errors should never be exposed directly.

---

## 15. Token Support

The API automatically supports:

- SPL Token
- Token-2022

Applications never select token instructions manually.

The SDK determines the correct token program using the registered asset configuration.---

## 16. Transaction API

Applications explicitly submit transactions.

Example:

```typescript
await client.send(transaction)
```

The SDK never submits transactions implicitly.

---

## 17. Configuration

Example:

```typescript
new BabycowansClient({

    connection,

    programId,

    commitment

})
```

Configuration remains immutable after client creation.

---

## 18. Documentation

The API documentation includes:

- quick start
- installation
- examples
- account reference
- payment examples
- token gating examples
- reward examples
- API reference

Every public API includes executable examples.

---

## 19. Versioning

The API follows semantic versioning.

Major releases may introduce new protocol capabilities.

Minor releases remain backward compatible.

---

## 20. Security

The API never:

- stores private keys
- manages wallets
- bypasses protocol validation
- performs hidden RPC calls
- modifies protocol rules

Wallet authorization always remains external.---

## 21. Design Guarantees

The API guarantees:

1. Deterministic behavior.
2. Strong typing.
3. Stable public interfaces.
4. Canonical account access.
5. Automatic PDA derivation.
6. Automatic Token-2022 compatibility.
7. Explicit transaction submission.
8. Complete account decoding.
9. Version-aware protocol support.
10. No duplicated business logic.

---

## 22. Compatibility

The API supports:

- Solana Mainnet
- Solana Devnet
- Solana Local Validator

No environment-specific business logic exists inside the API.

---

## 23. Future Evolution

Future API extensions require:

- specification update
- implementation
- SDK update
- documentation update
- release notes

Existing Version 1 APIs remain stable.

---

## 24. Version 1 Scope

Version 1 exposes every protocol capability required by:

- wallets
- payment applications
- token-gated services
- reward platforms
- business integrations

Applications should not require custom wrappers around the SDK.

---

## 25. Conclusion

The Babycowans Protocol API provides the single canonical interface between applications and the Babycowans Protocol.

Every public operation is deterministic, strongly typed, fully documented, and directly aligned with the protocol specification.
