# Babycowans Protocol Code of Conduct

## Purpose

Babycowans Protocol V1.0.0 is maintained as a professional open-source developer project. Participation in repository issues, pull requests, reviews, discussions that may be enabled in the future, and other project-controlled collaboration surfaces must remain constructive, technically focused, and respectful.

## Expected conduct

Participants are expected to:

- communicate respectfully and in good faith;
- keep technical criticism focused on code, documentation, protocol behavior, evidence, and engineering decisions;
- provide reproducible information when reporting defects;
- respect privacy, credentials, unpublished vulnerability information, and confidential security details;
- avoid harassment, discrimination, threats, intimidation, personal attacks, impersonation, spam, and deliberately disruptive behavior;
- follow the repository's security-reporting requirements for vulnerabilities and sensitive security findings.

## Unacceptable conduct

The following behavior is not acceptable in project-controlled spaces:

- harassment, abusive or degrading language, or targeted hostility;
- discriminatory conduct based on personal characteristics or identity;
- threats of violence or encouragement of harm;
- publication of private information, credentials, secrets, or sensitive personal data without authorization;
- deliberate disclosure of an unremediated vulnerability through a public repository surface;
- repeated bad-faith disruption, spam, manipulation, or attempts to evade repository moderation.

## Scope

This Code of Conduct applies to Babycowans-controlled repository collaboration surfaces and to conduct undertaken while representing the project in an official project capacity.

It does not create authority over unrelated third-party spaces. GitHub's own Terms of Service, Acceptable Use Policies, and platform moderation rules continue to apply independently.

## Reporting and enforcement

For conduct that violates GitHub platform policy, use GitHub's built-in reporting and abuse-reporting mechanisms where available.

For non-sensitive repository-governance concerns, a GitHub Issue may be used when public discussion is appropriate. Do not place sensitive personal information, private credentials, or confidential security details in a public Issue.

Security vulnerabilities are not conduct reports and must follow the private process defined in [SECURITY.md](SECURITY.md), including GitHub Private Vulnerability Reporting where available.

Repository maintainers may remove or edit project-controlled content, close or lock interactions, restrict participation, or take other repository-level moderation actions that are available through GitHub when conduct materially violates this policy. Enforcement decisions should be proportionate to the behavior, the available evidence, prior warnings where appropriate, and the safety of project participants.

## Good-faith enforcement

This policy is intended to protect productive technical collaboration, not to suppress disagreement. Good-faith technical criticism, evidence-based review, and respectful disagreement about design or implementation are permitted.

## Changes

Material changes to this Code of Conduct must remain consistent with the Babycowans Protocol V1.0.0 repository-governance contract and must not silently create new release, tag, branch, or protocol-version identities.
